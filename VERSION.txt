V0.6.0
	su-fw, the firmware tool for a command shell, scripts and AI agents: a console program next to BuildAI-SerialUtility in every package (same bin folder, same bundled tools) that runs the Firmware tab's operations with the very same code - su-fw status (the board, its flash layout, --mcu for the CC1310's version and role), partitions (the image's partition table: offsets, sizes, what fits), pull, flash-soc (--all or --partitions boot,rootfs; a running board is put into Loader mode over ADB without a question), mcu-info, mcu-update, mcu-set-role and pull-flash (the tab's Pull & Flash).
	Made for agents: the log on stdout as time-stamped lines or, with --json, one JSON object per line (log, progress, step, done with the command's results), the result as the exit code (0 done, 1 failed, 2 usage, 3 no board, 4 SSH, 5 timeout or Ctrl+C), --log FILE, --quiet, --timeout, and a --help for every command that explains every option with examples.
	Safe without anyone watching: secrets only from --password-env, --password-stdin, --identity or the passwords the app remembered, never printed; an unknown host key only with --accept-host-key, a changed one never; --yes (and a non-terminal stdin) asks nothing, while a person at a terminal is asked for the host key and the password (no echo). Ctrl+C and --timeout end the waiting phases but never a flash write in progress - su-fw stops right after it, and a cancel that lands in the ADB wait says "interrupted after the image was written; the ADB wait was cancelled".
	One firmware operation per PC: the Firmware tab and su-fw share a lock in the app's data folder, so a second operation (the tab while su-fw flashes, su-fw while the tab does, two su-fw) is refused at once with "another firmware operation is running (<program>, pid <n>)" (su-fw exits 1) and the board status pauses meanwhile instead of talking to the board in the middle of the other's write.
	The tools are shielded from what reaches su-fw: upgrade_tool and adb run without su-fw's console on Windows (as the GUI always ran them) and in a process group of their own on Linux, so Ctrl+C, Ctrl+Break, closing the console window or terminal (SIGHUP) and signals to su-fw's group never end a write; only a kill of the whole process tree still does, so a harness's own timeout must exceed --timeout plus the write.
	It uses the app's settings (SSH profiles, Preferences > Firmware, the flash layouts remembered per board) and changes none of them except a board's layout once it has read it. New test suite tst_firmwarecli (68 cases on the fake tools, the in-process SSH server and the fake CC1310, plus the built executable); the installer, the zip, the tarball and both CI deploy checks carry and start su-fw.

V0.5.1
	Firmware tab, SoC: Loader mode now flashes the way Rockchip's SocToolKit does on its Download page - the image is unpacked (upgrade_tool EXF) and every partition is written on its own (upgrade_tool WL at the partition's offset with the partition's size in sectors - the size is what lets upgrade_tool write a jffs2 image such as userdata - then RD to restart the board). This needs no chip check, so the Node board's U-Boot, which answers upgrade_tool UF's chip check with zeros ("Check Chip Fail"), is flashed in Loader mode without any change to it; the U-Boot chip-info patch is optional now. MASKROM mode still writes the whole image with UF.
	Partition table: once an image is selected the tab lists its partitions with a checkbox each - name, image file, flash offset, partition size, image size - so one partition (say boot or rootfs) can be flashed alone; All / None set the checkboxes, the label counts the checked partitions and their size. Rows that are not in the board's layout or whose image is larger than the partition are disabled and say why. Pull & Flash writes every partition.
	The flash layout (an mtdparts string) comes from the image itself when its env.img carries one - the layout the build was made for, so a board already in Loader mode is flashed without asking it - else from the board: the mtdparts of its kernel command line, read once from a running board over ADB and remembered per board, and read again by every flash before the board is rebooted into Loader mode. When both are known and differ the image's is used and the log shows both; the partition label says where the layout came from. Every image is checked against its partition before the first byte is written, a failing write stops with upgrade_tool's last lines, and the log lists the partitions, the layout and the method used.

V0.5.0
	Firmware tab (File > Firmware Update, Ctrl+Shift+U): one tab replaces the whole Windows flashing routine for the Node board (Rockchip RV1106 SoC + CC1310 RF MCU) - pull the newest build, flash the SoC, update the MCU - over the board's single USB-C cable, with no vendor GUI, no USB-serial adapter and no MASKROM button; Pull & Flash does all three with one button.
	Source: pulls update.img from the Linux build machine over the existing SSH stack (profiles, known_hosts, remembered passwords, SFTP with the shell fallback), shows the remote size, time and git describe first, skips an unchanged image, downloads to a .part file and checks the RKFW magic, keeps the previous image so a bad build can be rolled back; Use local image... is the offline route.
	SoC: a status line (ADB device, Loader, Maskrom, no board, missing driver) refreshes every 2 s; Flash SoC puts the board into Loader mode with adb reboot loader (or through a connected serial / SSH tab after asking, or MASKROM), runs upgrade_tool with a progress bar, requires "Upgrade firmware ok", waits for the board to return on ADB and shows its kernel version and uptime; Cancel only while waiting, never while the flash is written.
	MCU: the CC1310 UART updater protocol (COBS framing, CRC16, package CRC32, the fw_update state machine with retries and resume) is implemented natively in C++ and reaches the chip through the SoC (adb forward + rfmcu bridge); the package picker checks header and CRCs and shows target, version and size; the running version and role are read through ADB, the rx / tx role is pre-selected and confirmed by you; Update MCU and Set role show progress per acknowledged block and the restart banner.
	Node quick commands: a new "Node" group comes first in the defaults - reboot loader, rfmcu console, the CC1310 CLI (help, version, sys, stack, uart, power, bat, rx status, rx dump on/off, tx status, bootloader) and ~. to leave the console - with usage tooltips. An existing quick_commands.json (file version 1) gets the group added once in front of your commands and is saved as version 2; nothing else in it changes.
	Bundled tools in tools/ next to the executable (plain files in third_party/ with provenance and licences): Rockchip upgrade_tool (Windows 2.37, Linux 2.26) with its license text, Rockchip's adb with its two DLLs, and the Rockchip USB driver installer (DriverAssistant 5.14); the Windows installer has an optional "Install the Rockchip USB drivers" task, the tab offers the installer when a Rockchip device has no driver, and Preferences > Firmware can point to other copies of the tools.
	Packaging and CI: cmake --install ships bin/tools, both CI jobs check that the tools landed; new test suites tst_ccprotocol, tst_mcuupdater, tst_firmwaretools, tst_imagepuller and tst_firmwaretab run against fake tools, a C++ fake CC1310 and the in-process SSH server, without hardware.

V0.4.0
	Keyboard: while a session is connected every key that is not an application shortcut goes to the device, so Ctrl+W (delete word) and the other bare Ctrl+letter combinations now reach a shell; Close Session moved to Ctrl+Shift+W. Every shortcut is configurable in Preferences > Keyboard (with conflict detection and Restore Defaults).
	Tab selection: a Window menu lists the open sessions; Alt+1..Alt+9 select a tab, Ctrl+PageDown / Ctrl+PageUp cycle next to Ctrl+Tab / Ctrl+Shift+Tab, a middle click on a tab closes it.
	SSH: the password / passphrase prompt offers "Remember" for every connection, not only for stored profiles - an ad-hoc user@host and a key file are remembered per target / per key (Windows DPAPI), so the next connection needs no typing.
	SSH file transfer works on boards without SFTP (dropbear): when the sftp subsystem is refused, upload and download fall back to plain shell commands over an exec channel (cat, wc -c, test, chmod, rm), with the method shown in the transfer dialog; transfers verified against a real OpenSSH server from the real window.
	Serial: automatic baud-rate detection - pick "Auto" in the baud list and the tool listens at the candidate rates (115200, 1500000, 921600, ... configurable in Preferences > Connection) until the output reads as text, applies the rate and tells you; while running with Auto, output that turns into garbage (the board switched from 1500000 to 115200) triggers a new detection; Session > Detect Baud Rate (Ctrl+Shift+B) runs it on demand for a fixed rate too. The built-in simulators now have native rates and produce wrong-rate garbage like a real UART.

V0.3.0
	SSH sessions (File > New SSH Session..., Ctrl+Shift+T): the same terminal, quick commands, command input, hex view, logging, log replay and mark mode over SSH. Type user@host[:port] (also ssh:// URLs, [IPv6]:port and Host aliases from ~/.ssh/config) or pick a saved profile, then Connect.
	Host keys are verified against ~/.ssh/known_hosts (the file the ssh command uses): fingerprint confirmation for new hosts, and the "REMOTE HOST IDENTIFICATION HAS CHANGED" warning with an explicit replace step when a board was reflashed.
	Authentication: ssh-agent (Linux/macOS), key files (~/.ssh/id_ed25519, id_ecdsa, id_rsa or a chosen file, with passphrase prompt), password and keyboard-interactive, in the order the server offers; passwords and passphrases can be remembered per profile (Windows DPAPI; obfuscated elsewhere and labelled as such).
	SSH profiles (Edit > SSH Profiles...): name, host, port, user, authentication method, key file, saved password, remote command, startup command, terminal type, keep-alive, timeout, compression, ProxyJump, alternative known_hosts file and local port forwards; JSON import/export (never with secrets); the connection bar lists the profiles and the last ten ad-hoc targets.
	The remote shell follows the terminal size automatically (window-change requests); keep-alives detect dead links; a dropped connection reconnects with backoff using saved credentials only, while a clean "exit" ends the session without reconnecting.
	SFTP file transfer on the same connection: Session > Upload File to Remote... / Download File from Remote... with progress and cancel; dropping a file onto an SSH terminal uploads it.
	Preferences > SSH: default known_hosts file, identity file, terminal type and keep-alive interval. SSH tabs are restored on the next start (not connected). The status bar shows the host key type and the authentication method.
	Built on libssh 0.11.1 (fetched and built from source, OpenSSL backend) and shipped with every package; the new test suites run against an in-process SSH server on both Windows and Linux CI.

V0.2.0
	Pause output while selecting (cmd.exe mark mode): starting a mouse selection freezes the display while incoming bytes queue up; Enter copies the selection to the clipboard and resumes, Esc cancels; on by default, switchable in View > Pause Output While Selecting and in Preferences > Terminal. Logging and the hex view keep receiving data while the display is paused.
	cmd.exe-style right click: pastes the clipboard, or copies the selection when text is selected; the context menu moves to Shift+right click and the Menu key. On by default, switchable in View and Preferences.
	Clear (toolbar / Session menu / Ctrl+Shift+L) now wipes the screen, the scrollback and the hex view; Reset Terminal remains the full VT reset.
	CI/CD fixes for GCC (warnings as errors), Qt deploy with a relative install prefix, and an environment-independent Linux self-containment check.

V0.1.0
	Initial release of BuildAI Serial Utility.
	Multi-tab serial terminal with VT100/ANSI emulation (colours, cursor control, scroll regions, scrollback).
	Full serial parameter control: baud (incl. 1500000 for Rockchip), data bits, parity, stop bits, flow control, DTR/RTS, break.
	Hot-plug aware port list with auto-reconnect when a board reboots or is re-plugged.
	Line-mode command input with history, hex send, C-style escapes, and configurable line endings.
	Quick-command bar with editable macros (Linux / U-Boot / MCU presets).
	Send text or binary files with configurable pacing.
	Session logging (raw / timestamped text / hex dump) and hex-dump view.
	System log dock, About / Version dialogs, English + Simplified Chinese UI.
	Automated GUI test suites (Qt Test, offscreen) for the terminal widget, session widget, main window and dialogs, next to the core unit tests.
	CI/CD: GitHub Actions builds Ubuntu (GCC) and Windows (MSVC) with warnings as errors, runs all suites, and publishes the Windows installer (Inno Setup), portable zip and Linux tarball with checksums on v* tags.
